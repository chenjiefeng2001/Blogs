# TCP 三次握手详解（交互式图解）

TCP（Transmission Control Protocol）在传输数据之前必须先建立连接。这个过程被称为**三次握手**（Three-Way Handshake），它通过三次消息交换确保双方都具备收发数据的能力。

本文通过一个**可交互的 SVG 动画**，把抽象的文字流程变成你可以逐帧观察的图形状态变化。

## 为什么需要三次握手？

在深入细节之前，先思考一个问题：**为什么不是两次或四次？**

- **两次不够**：如果客户端只发一次 SYN 就直接建立连接，无法防止历史延迟的数据包突然到达服务器，造成资源浪费。
- **三次刚好**：客户端与服务器对**初始序列号（seq）**达成共识，保证了双向通信的起点一致。

## 分步讲解

### 第一步：SYN（客户端发送）

客户端向服务器发送一个 SYN 报文，其中包含客户端选择的初始序列号（例如 `seq = x`），标志着客户端尝试建立连接。

### 第二步：SYN + ACK（服务器回应）

服务器收到 SYN 后，如果同意建立连接，就会回复一个 **SYN + ACK** 报文：
- `ACK`：确认收到客户端的 SYN（`ack = x + 1`）
- `SYN`：服务器自己选择的初始序列号（`seq = y`）

这个包同时向客户端证明：**我收到了你的报文，并且我也准备好了。**

### 第三步：ACK（客户端确认）

客户端收到 SYN + ACK 后，发送一个 ACK 报文（`ack = y + 1`）。一旦服务器收到这个 ACK，连接就进入了 **ESTABLISHED** 状态，双方可以开始收发数据。

## 总结

三次 handshake 的核心目标是**双向同步初始序列号**：

| 步骤 | 方向 | 内容 | 目的 |
| ---- | ---- | ---- | ---- |
| 1 | Client → Server | SYN (seq=x) | 客户端尝试建立连接 |
| 2 | Server → Client | SYN + ACK | 服务器确认并回应自己的序列号 |
| 3 | Client → Server | ACK | 客户端确认服务器的序列号 |

最后一个 `ACK` 到达后，连接进入 **Established**，客户端与服务器就能够基于可靠的、有序的、双向的字节流进行通信了。
