# 浏览器事件循环详解（交互式图解）

JavaScript 是一门**单线程**语言：同一时刻只能执行一段代码。但浏览器却能在执行脚本的同时响应用户输入、处理定时器回调、完成网络请求——这背后的调度机制就是**事件循环**（Event Loop）。

本文通过一个**可交互的 SVG 动画**，把"调用栈、微任务队列、宏任务队列"这三个抽象概念变成可以逐帧观察的图形状态变化。

## 三个核心角色

- **调用栈（Call Stack）**：同步代码的执行场所，蓝色标识。函数调用时入栈，返回时出栈。
- **微任务队列（Microtask Queue）**：`Promise.then`、`queueMicrotask`、`MutationObserver` 的回调排在这里，琥珀色标识。
- **宏任务队列（Task Queue）**：`setTimeout`、`setInterval`、I/O、UI 事件的回调排在这里，绿色标识。

事件循环的规则很简单：**每清空一次调用栈，先处理完微任务队列中的所有任务，再从宏任务队列取出一个任务执行。**

## 分步讲解

### 第 0 步：初始状态

三个队列全部空置。调用栈（蓝）、任务队列（绿）、微任务队列（琥珀）都在等待任务。

### 第 1 步：main() 入栈

脚本开始执行，`main()` 作为同步代码进入**调用栈**。注意此时两个队列仍然是空的。

### 第 2 步：main() 调度了两个异步任务

`main()` 内部调用了 `setTimeout` 和 `Promise.then`：

- `setTimeout` 的回调进入**宏任务队列**（绿）
- `Promise.then` 的回调进入**微任务队列**（琥珀）

关键点：两个回调此刻都**没有执行**，只是在排队。

### 第 3 步：main() 执行完毕

同步代码跑完，调用栈清空。此刻调用栈与队列之间的连线断开——这正是事件循环"tick"的开始。

### 第 4 步：微任务优先

调用栈为空后，事件循环**先清空微任务队列**：promise 回调从微任务队列被取出，进入调用栈执行。注意连线的变化——微任务队列到 promise 的边消失，取而代之的是调用栈到 promise 的新边。

**这就是"微任务优先于宏任务"的可视化证据：即使 `setTimeout(fn, 0)` 先被调度，`Promise.then` 的回调也先执行。**

### 第 5 步：promise 回调执行完毕

调用栈再次清空。微任务队列已空，事件循环转向宏任务队列。

### 第 6 步：取出宏任务

timeout 回调从任务队列被取出，进入调用栈执行。

### 第 7 步：本轮事件循环结束

timeout 回调执行完毕，调用栈、微任务队列、宏任务队列全部清空。下一轮 tick 等待新的任务到来。

## 用代码验证

把下面的代码粘贴到浏览器控制台，输出顺序和图解完全一致：

```js
console.log('1');                                 // 同步：立即执行
setTimeout(() => console.log('4'), 0);            // 宏任务：进入任务队列
Promise.resolve().then(() => console.log('3'));   // 微任务：进入微任务队列
console.log('2');                                 // 同步：立即执行

// 输出：1 2 3 4
```

执行过程对照图解：

1. `console.log('1')`、`console.log('2')` 是同步代码，对应**第 1-3 步**（main 入栈到出栈）；
2. `setTimeout` 与 `Promise.then` 只负责排队，对应**第 2 步**；
3. 栈空后微任务先执行，`'3'` 先于 `'4'` 输出，对应**第 4-5 步**；
4. 最后处理宏任务，`'4'` 输出，对应**第 6-7 步**。

## 常见误区

- **`setTimeout(fn, 0)` 不是立即执行**：它只是把回调排入宏任务队列，至少要等到当前同步代码和所有微任务执行完。
- **微任务不是"更快的 setTimeout"**：二者是不同队列，事件循环在每次 tick 中**全部清空**微任务，但每次只取**一个**宏任务。
- **`await` 后面的代码是微任务**：`async/await` 是 Promise 的语法糖，`await` 之后的语句等价于放进 `then` 的回调。

## 总结

| 阶段 | 队列 | 典型来源 | 处理时机 |
| ---- | ---- | -------- | -------- |
| 同步执行 | 调用栈 | 主脚本、函数调用 | 立即，栈空之前 |
| 清空微任务 | 微任务队列 | `Promise.then`、`queueMicrotask`、`await` | 每次栈空后**全部**处理 |
| 取宏任务 | 任务队列 | `setTimeout`、`setInterval`、I/O、事件 | 每轮 tick 只取**一个** |

事件循环的核心可以浓缩成一句话：**同步跑完 → 微任务清空 → 宏任务取一 → 循环往复。**

理解了这个顺序，`setTimeout` 与 `Promise` 的输出顺序、`await` 的执行时机就都不再是背诵的结论，而是可以一步步推导的自然结果。
